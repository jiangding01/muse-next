## 0. 文档目的与使用方式

### 0.1 这份文档是什么

这是交给视觉设计环节（Claude Design）的**输入说明书**，不是实现方案，也不是
技术设计文档。它回答三个问题：

1. 现在的界面实际长什么样、每个控件真实做了什么（第 2 章）；
2. 界面需要承载哪些功能、每条功能的来源与边界（第 3 章）；
3. 设计时哪些是不能动的硬约束、哪些是开放待设计的（第 4–7 章）。

### 0.2 怎么用

- **先读第 1、3、4 章**：定位 + 功能清单 + 信息架构，决定画哪些画面；
- **第 5、6 章是视觉与交互的约束集合**，设计稿需要逐条能对上；
- **第 9 章是交付物清单**，设计产出按那份清单组织；
- **第 10 章是开放问题**，每条都给了推荐答案，需要用户拍板后才落设计。

### 0.3 硬约束 vs 开放项

**硬约束（设计不得违反，违反会导致方案无法实现）**

| # | 约束 | 来源 |
|---|---|---|
| H1 | 乐谱几何由 `src/notation/**` 的纯函数布局决定，界面不得要求"把谱面整体等比拉伸填满容器"——换行由可用宽度触发的重排实现 | `HANDOFF.md` §30.1（D7）、`src/renderer/components/notation/ScoreView.tsx` |
| H2 | 缩放语义固定：画布 CSS 宽 = `layout.width × cssPixelsPerUnitAtZoom1 × zoom`；`availableWidth = 容器像素 ÷ (cssPixelsPerUnitAtZoom1 × zoom)`。放大 → 换行更早、每行小节更少 | `src/notation/layout/metrics/shared.ts`、`ScoreView.tsx` |
| H3 | 四种记谱中 Jianpu / TAB / Chord 是自绘 SVG（React `SvgTree`），Staff 由 VexFlow 直接写 DOM，两类的可定制程度不同（见 5.4） | `HANDOFF.md` §30.1 T7.4 |
| H4 | 五线谱字形来自 VexFlow 内嵌 Bravura（+ Academico），**不可替换、不可由设计指定其它乐谱字体**；原软件的 `MAESTRO.TTF` 明确不得打包 | `HANDOFF.md` §5.4、§30.1 T7.4 |
| H5 | Electron `sandbox: true` + `contextIsolation: true`，渲染进程只能通过显式 IPC 通道访问文件系统；界面不能假设可以直接读写任意路径 | `src/main/main.ts`、`HANDOFF.md` §24 |
| H6 | 渲染层永不产生 `error` 级诊断——最坏情况是"一页全是占位块"，界面必须始终有谱面可画，不存在"渲染失败整页空白"这一状态 | `src/notation/model/diagnostics.ts` 文件头 |
| H7 | 解析层同样永不抛异常，任何无法结构化的内容都以诊断呈现；不存在"打不开的文件"这一状态（只存在"解析出大量诊断"） | `src/renderer/app/store.ts` 文件头 |
| H8 | 中英文混排是常态：语料标题/歌词/声部名多为中文，字段名/诊断码/源码为 ASCII | `docs/JCX_SPEC.md` §4、`docs/generated/` 证据摘要 |
| H9 | 诊断分两条独立通道：`jcx.*`（解析）与 `muse.render.*`（渲染），**不得在界面上合并成一个列表而抹掉来源** | `src/notation/model/diagnostics.ts` §4.2 |

**开放项（本轮设计要拍板的）**：界面字体、配色体系（含深色主题）、图标风格、
三栏的折叠/拖宽行为、菜单与工具栏的职责划分、快捷键、空/错误状态的视觉语言、
打印预览的页面呈现、诊断面板的位置与分级呈现。

## 1. 产品定位与用户

### 1.1 产品是什么

Muse Next 是停止维护的 Muse Pro 2.70 的 clean-room TypeScript/Electron 重建。
原软件是一款**中文吉他/简谱制谱软件**，文档格式 `.jcx` 是 ABC notation 的派生
文本格式（`HANDOFF.md` §6）。Muse Next 的第一优先级是**能打开旧文件并正确显示**，
其次才是编辑与播放（`HANDOFF.md` §2.2）。

### 1.2 目标用户

- **主用户**：Muse Pro 2.70 的老用户。中文母语，习惯简谱 + 吉他 TAB + 和弦图的
  组合，手上有存量 `.jcx` 文件（多为 GB18030 编码），原软件在新系统上已无法
  正常运行。他们对"专业制谱软件"的心智模型来自 Muse 本身，不是 Sibelius/MuseScore。
- **次用户**：需要把旧谱迁出的人——打开、校对、导出 PDF/打印，不一定要编辑。
- **开发者自用**：当前阶段（M2 刚封板）实际使用者是开发者本人，用于人工 smoke
  与诊断校对；这个用途不应主导设计，但"诊断可见、可定位"必须保留。

### 1.3 目标平台

macOS 与 Windows 桌面（Electron 44，React 19）。Linux 有打包器配置但不是目标。
当前窗口默认 1440×920，最小 1080×720（`src/main/main.ts`）。无移动端、无 Web 版。

### 1.4 核心场景

| 场景 | 描述 | 当前状态 |
|---|---|---|
| S1 打开旧谱 | 用系统对话框选一个 `.jcx`，自动识别编码，立即看到谱面 | 已实现（单通道 IPC） |
| S2 查看/校对 | 翻阅谱面、放大缩小、看哪些内容被降级处理了、点击定位 | 已实现（锚点高亮 + 两套诊断列表） |
| S3 编辑源码 | 在源码面板里改文本，重新解析，看谱面变化 | 半实现（改了要手动点 Reparse，不能保存） |
| S4 导出/打印 | 导出 PDF/图片，或直接打印 | 未实现（M5，`HANDOFF.md` §48/§49） |
| S5 可视化编辑 | 选区、光标、插入删除音符、撤销重做 | 未实现（M3，`HANDOFF.md` §44） |
| S6 播放 | MIDI 播放、播放光标、逐声部音量/乐器 | 未实现（M4，`HANDOFF.md` §46/§47） |

## 2. 现状 UI 盘点

> 本章描述的是**当前代码里真实存在的行为**，不是规划。设计时这些都是
> "已实现但需要重新设计"的基线。所有坐标/尺寸取自 `src/renderer/styles/global.css`。

### 2.0 整体外壳

`src/renderer/app/App.tsx`：竖直两段——顶部 `Toolbar`（固定 64px），下方
`app-grid` 三栏：`238px | minmax(520px, 1fr) | 370px`。

- 窗口背景 `#f4f1e9`，界面底色 `#e8e4db`，面板 `#f8f5ee`，纸面 `#fffdf7`，
  强调色 `#2d5b4f`（墨绿），次级文字 `#756f65`。
- 界面字体当前写死为 `Inter, ui-sans-serif, -apple-system, ...`——**没有为中文
  指定任何字体**，中文走系统兜底。这是明确的待设计项。
- 唯一响应式断点：`max-width: 1180px` 时**整个右栏被 `display: none` 隐藏**，
  左栏收窄到 210px。这是粗暴处理，需要重新设计。

### 2.1 顶部工具栏（`Toolbar.tsx`）

三列网格 `270px | 1fr | 260px`，整条设为窗口拖拽区（`-webkit-app-region: drag`），
操作区单独 `no-drag`。

| 区域 | 内容 | 真实行为 |
|---|---|---|
| 左 | 方形品牌标记 `M` + "Muse Next" + 副标题 "Legacy Muse reimplementation" | 纯装饰，不可点 |
| 中 | `Open .jcx` 主按钮 | 调 `window.museDesktop.openScore()` → 主进程 `dialog.showOpenDialog` |
| 中 | `Reparse` 次级按钮 | 用当前 textarea 内容重新跑 `loadJcx`，刷新谱面与诊断 |
| 中 | 缩放三连：`−` / 百分比 / `+` | 步进 0.25，范围 clamp 到 [0.5, 3]；中间按钮点击=重置到 100%；`aria-label` 为中文"缩小/重置缩放/放大" |
| 右 | 文件名（`filePath` 取 basename）+ 编码标签（`utf8`/`gb18030`/`—`） | 纯展示，`title` 属性挂完整路径 |

**已知问题**：按钮文案中英混杂（按钮是英文、aria-label 是中文）；basename 用
`split('/')` 取末段，Windows 路径分隔符下会取到整串；缩放没有下拉选择常用档位；
没有"适应页宽/适应整页"这类制谱软件常见档位。

### 2.2 左侧 Document 侧栏（`DocumentSidebar.tsx`）

面板标题 `Document` + 右侧药丸 `N voices`。两段内容：

- **SCORE**：定义列表四行——`Title`（`score.titles[0]`，缺省 `Untitled`）、
  `Meter`、`Key`、`Tempo`（三者都取 `.raw` 原文，缺省显示破折号）。
  标签列固定 60px，值列单行省略号截断。
- **VOICES**：每个声部一张卡片——左侧 44px 的 style 徽标（`tab` 绿 / `jianpu` 黄 /
  `staff` 蓝，缺省灰底显示破折号），右侧主行是 `voice.name`（缺省 `Voice <id>`），
  副行是 `<id> · MIDI <instrument> · vol <volume>`。

**已知问题**：整栏是只读的——不能点声部定位到谱面、不能显隐/独奏/折叠声部；
标题只显示第一条（`T:` 可重复，副标题被丢弃）；不显示 `X:` 参考编号、
`L:` 单位音长、`%%` 指令、文本块；没有滚动定位能力；全英文标签。

### 2.3 中间乐谱区（`ScoreWorkspace.tsx` + `ScoreView.tsx`）

**页签条**：`Score` / `Source` / `Print Preview` 三个按钮，`Score` 硬编码
`className="active"`。**三个按钮都没有 onClick——页签完全是静态装饰**，点击无任何
反应。这是当前界面最明显的"假控件"。

**纸面**：`.score-page`，最大宽 820px、最小高 1000px、内边距 54/64px、白纸
`#fffdf7` + 投影，居中在 `#dfdbd2` 的舞台上。**纸面是无限长的单页**，没有分页、
没有页边距标尺、没有页码。

纸面内自上而下三块：

1. **谱面头部**（`ScoreHeaderView.tsx`）：居中标题（Georgia 26px）、副标题、
   一行元信息（key / meter / tempo 的文本化结果）、右对齐 credits、左对齐 notes、
   左对齐文本块（`%%begintext`）。整个 `<header>` 带 `document` 级锚点，可被
   文档级诊断高亮（2px 墨绿描边）。
2. **声部区**（`.score-voices`，纵向排列，间距 24px）：每个声部一个 `<section>`，
   带 `data-voice-id` 与 voice 级锚点。四种分支：
   - `jianpu` → 自绘 SVG（`jianpu-*` class）
   - `tab` → 自绘 SVG（`tab-*` class）
   - `staff` → VexFlow 画进独占 host（`.staff-canvas`），**异步**（先
     `await document.fonts.ready`）
   - 缺席/未知 style → 虚线框占位：一行大写小标签 + 一段等宽字体的事件文本摘要
3. **渲染诊断面板**（`DiagnosticsPanel.tsx`）：**当前渲染在纸面内部、谱面正下方**，
   列表项 = 诊断码（9px 等宽）+ 文案，按 info/warning 左边三色条，选中态浅黄底。
   这是明显的位置错误——诊断不该印在"纸"上。

**和弦图区**（`ChordDiagram.tsx`）：纸面底部一段 `Parsed guitar chords`，右侧
计数 `N from %%gchord`，下方 flex-wrap 网格排列和弦图。每张图含和弦名、品位标签、
弦状态（`x`/`o`）、按弦圆点与指法数字（`showFinger` 三态控制）。**横按不渲染**
（`barres` 在当前 Domain 里恒为空，spec §10.1 横按记法 UNVERIFIED）。

**锚点联动**：点击谱面任意带 `data-anchor-key` 的节点 → 该 key 被选中 → 谱面
对应节点与诊断列表对应条目同时高亮；反向点诊断条目也一样。**不做源码行定位**
（`SourceRef` 是 AST 路径字符串，行级定位留给 M3）。换 `score` 时选中态清空。

**缩放**：见 H2。`ResizeObserver` 量 `.score-voices` 的真实 CSS 宽度；测不到时
退回固定 960 单位。

### 2.4 右侧 JCX Source 面板（`SourceInspector.tsx`）

四行网格：标题条 45px / textarea（1fr）/ 计数条 / 诊断列表（0.55fr）。

- **标题条**：`JCX Source` + 药丸 `N diagnostics`。
- **源码编辑器**：一个**裸 `<textarea>`**，深色 `#222521` 底、`#e5e1d8` 字、
  12px 等宽、`tab-size: 2`、关闭拼写检查、禁止 resize。没有行号、没有语法高亮、
  没有查找替换、没有折行控制、没有滚动同步。输入只更新 `source` 状态，
  **不自动重新解析**——必须去工具栏点 `Reparse`。
- **计数条**：`Headers`（= `titles.length + credits.length`）/ `Chords`
  （`chordShapes.length`）/ `Voices` 三组数字。
- **解析诊断列表**：只读，每条一行 `L<行号> <code>` + 文案，按
  info/warning/error 三色左边条（error 另加浅红底）。**不能点击、不能过滤、
  不能折叠、不能跳转**（文件头注释明确写着"M2 渲染层落地后再考虑与谱面联动"）。

### 2.5 主进程（`src/main/main.ts`）与 IPC

- **菜单**：没有自定义菜单——用的是 Electron 默认菜单（macOS 上是 Edit/View/
  Window/Help 等默认项，没有 File → Open/Save/Print）。
- **文件对话框**：`Open Muse Score`，过滤器 `Muse score (.jcx)` / `Text files
  (.txt/.abc/.tab)` / `All files`，只允许单选。
- **编码**：先用 `TextDecoder('utf-8', { fatal: true })` 严格试 UTF-8，抛错就
  按 GB18030 解（`iconv-lite`）。结果作为 `'utf8' | 'gb18030'` 回给渲染进程。
- **IPC 面**：只有一个通道 `muse:open-score`。**没有保存、没有另存为、没有
  最近文件、没有拖放打开、没有打印、没有导出、没有偏好设置**。
- **窗口**：单窗口，macOS 上关窗不退出、`activate` 时重开。无标签页、无多文档。

### 2.6 M2 遗留债务中与 UI 直接相关的条目

来源：`HANDOFF.md` §30.1「M2 遗留债务总表」。设计时需要知道这些"看起来不对"的
地方是**已知的、被记账的**，不是设计疏漏：

| 分类 | 内容 | 对设计的影响 |
|---|---|---|
| 视觉 | TAB 的 `x` 品位字形比数字矮，略高于弦线 | 字形基线策略需要视觉裁决 |
| 视觉 | TAB 不做 beam grouping，连续八分音符各画各的减时线 | 密集段落观感偏碎 |
| 视觉 | TAB 休止画 `z`/`Z`/`@` 原字符，不用休止符号 | 谱面上会出现裸字母 |
| 视觉 | 简谱附点画在数字右侧、延音线之前（`X . _ _ _`），与简谱习惯相反 | 需要设计确认目标形态 |
| 视觉 | 头部字号在 CSS 与 `layout/metrics` 双来源，未统一 | 设计给的字号 token 需要说明作用于哪一侧 |
| 视觉 | 歌词按列左对齐，居中留作 polish | 歌词行观感偏左 |
| 视觉 | Staff 不做 beam；slur/歌词不画，只发声部级 info | 五线谱当前观感显著弱于简谱/TAB |
| 视觉 | Staff 不做行内两端对齐与密度校准 | 每行右端参差 |
| 视觉 | `keySignatureAccidentalReserve` 固定按 7 个升降号预留，偏宽 | 行首留白偏大 |
| 架构 | **a11y（无障碍）完全未做** | 第 7 章是从零开始，不是补丁 |
| 架构 | `ScoreHeaderTextLine.fontSize/width` 字段无消费方 | 头部字号尚未由 layout 驱动 |

> 每条标注：**来源**（HANDOFF/spec/代码路径）、**UI 涉及面**、**状态与边界**。

## 4. 信息架构与布局要求

### 4.1 三栏的取舍

当前三栏（Document / 谱面 / Source+诊断）是脚手架时期的开发者布局，**不适合
最终用户**：右栏对"只想看谱"的老用户是噪音，但对校对场景又是刚需。

设计要求：

1. **谱面是唯一主角**。默认布局下谱面应占据尽可能大的面积，两侧面板可收起。
2. **左栏**（文档/声部）应可折叠为图标条；展开宽度可拖拽，建议 200–360px。
3. **右栏**（源码 + 诊断）应可整体收起，且**默认在"浏览模式"下收起**。
   收起时需要有一个持久的入口（例如底部状态栏的诊断计数徽标）。
4. **诊断面板必须移出纸面**。建议放在底部可展开的抽屉，或并入右栏，
   但两条通道（解析/渲染）要能同时看见或用清晰的分段切换。
5. 三栏之间的分隔条可拖拽，拖动应有 hover/active 反馈与最小宽度限制。

### 4.2 页签的归属

当前 `Score / Source / Print Preview` 三个页签在中间栏，但 Source 又同时存在于
右栏——职责重复。需要裁决（见 10.2）。推荐：**中间栏只放谱面与打印预览两态，
源码永远属于右栏面板**；或者反过来，三者都在中间栏做真正的视图切换、右栏只留诊断。

### 4.3 最小窗口与断点

- 最小窗口 1080×720（当前值，可调整，但不应低于 960×640）。
- 断点建议三档而非当前一档：
  - **≥ 1440px**：三栏全开；
  - **1180–1440px**：右栏变为覆盖式抽屉或自动收窄；
  - **< 1180px**：左右两栏都折叠为图标条，谱面全宽，诊断走底部抽屉。
- **禁止**在任何断点下直接 `display: none` 掉一整个功能区而不给入口（现状问题）。

### 4.4 菜单栏与工具栏的职责

- **系统菜单栏**（macOS 顶栏 / Windows 窗口内菜单）承载完整命令集：
  File（新建/打开/最近/保存/另存/导出/打印/关闭）、Edit（撤销/重做/剪切复制粘贴/
  查找）、View（缩放档位/显示隐藏面板/主题/页签切换）、Score（声部显隐/跳转小节/
  页面设置）、Playback（M4 预留）、Help（帮助/关于/诊断说明）。
- **工具栏**只放高频操作：打开、保存（编辑模式下）、撤销重做（M3）、缩放、
  视图切换、诊断徽标。工具栏按钮需要有中文文案或明确图标 + tooltip。
- **状态栏**（建议新增）：文件名、编码、脏标记、诊断计数（分级）、缩放百分比、
  当前选中锚点的简述。

## 5. 视觉与排版要求

### 5.1 总基调

**纸面为主，界面为辅**。现有配色（暖米色界面 + 白纸 + 墨绿强调）方向正确，保留
"纸"的隐喻但提升精致度：纸面与界面底色对比足够让"纸"浮起来、投影克制不拟物；
界面饱和度低，不与谱面诊断色（红/黄/绿）争注意力；谱面留白模仿真实乐谱排版
（上下大于左右，标题区与第一条谱之间有呼吸）。

### 5.2 字体

| 用途 | 当前 | 要求 |
|---|---|---|
| 界面西文 | `Inter` + 系统兜底 | 需要指定；要求数字等宽可用（`font-variant-numeric: tabular-nums` 已在缩放标签用到） |
| 界面中文 | **未指定** | **必须指定**。需要覆盖 macOS（PingFang SC）与 Windows（Microsoft YaHei / HarmonyOS Sans 等）两端，并给出混排时的基线与字重对应关系 |
| 谱面标题 | `Georgia, 'Times New Roman', serif` | 中文标题走 Georgia 会退化到系统兜底衬线体，需要为中文标题单独指定衬线字体 |
| 源码 | `SFMono-Regular, Consolas, monospace` | 需要指定跨平台等宽栈，且要能正确显示中文歌词（等宽字体的中文回退需要验证） |
| 简谱/TAB 字形 | `ui-sans-serif, system-ui`（SVG 内 class） | 数字字形一致性是简谱可读性的关键，建议指定具体字体族并保证跨平台一致 |
| 五线谱字形 | VexFlow 内嵌 Bravura + Academico | **不可更换**（H4） |

字体加载策略需要注意：Staff 绘制前要 `await document.fonts.ready`，如果设计引入
Web 字体，会延长这个等待，需要配套骨架态（Z5）。

### 5.3 颜色系统

需要交付**浅色与深色两套** token。当前只有浅色，且全部写死在 `global.css` 的
字面色值里。

必须覆盖的语义槽位：

- **底层**：窗口背景、面板背景、纸面背景、分隔线、投影。
- **文字**：主文字、次级文字、禁用文字、反色文字（深底源码面板）。
- **强调**：主强调色（当前 `#2d5b4f`）、强调悬浮/按下态、选中高亮背景。
- **谱面墨色**：音符/谱线/小节线的墨色（当前 `#23211d` 系），要求**打印时
  可退化为纯黑**。
- **诊断三色**：info（当前 `#9fb0c4` 蓝灰）、warning（`#d0a74e` 琥珀）、
  error（`#c0715f` 砖红，仅解析通道会出现）。
- **降级语义色**：未知/越界文本（当前 `#a34632`）、fallback 角标（`#c98a2c`）、
  未知虚线框（红色虚线）、灰化的"不参与渲染"元素。
- **声部 style 徽标**：tab 绿 / jianpu 黄 / staff 蓝 / 未知灰（当前四色已存在，
  需要纳入 token 并给深色版本）。
- **打印**：必须给出一套**黑白（或极低彩度）打印样式**——谱面墨色转纯黑、
  诊断标记与高亮**全部不打印**、降级角标是否打印需裁决（推荐不打印）。

### 5.4 自绘层 vs VexFlow 层的可定制边界（重要）

- **Jianpu / TAB / Chord**：SVG 节点带语义 class（`jianpu-digit`、`tab-fret-text`、
  `chord-diagram .finger-dot` 等），颜色/描边/字体**可以由 CSS 完全控制**；
  但**几何（位置、宽度、间距）由 `src/notation/layout/metrics/**` 的常量决定，
  不能由 CSS 改**。设计要改间距需要改 metrics 常量，属代码改动。
- **Staff**：VexFlow 自己画，class 带 `vf-` 前缀。可控的是颜色（已有若干
  `.vf-*` 规则）与外层容器；**字形、谱线、符干等几何不可由设计自由调整**。
  因此设计稿里五线谱的"理想形态"要标注哪些是可实现的、哪些是许愿。

### 5.5 密度与间距

- 建议给出一套 4px 基准的间距刻度（当前代码里 3/4/6/7/8/9/11/12/14/18/24/28/32
  混用，缺乏节奏）。
- 面板标题条当前固定 45px、工具栏 64px，可调整但需保持"工具栏 > 面板标题条"
  的层级感。
- 诊断列表当前 10px 字号偏小，需要重新定密度（建议给"紧凑/舒适"两档）。

### 5.6 图标与动效

- 图标：线性、1.5px 描边、24px 网格，与中文笔画重量匹配。需要：打开、保存、
  撤销/重做、缩放（放大/缩小/适应）、面板折叠、声部显隐、播放/暂停/停止（M4
  预留）、诊断三级、记谱类型四种、打印、导出。
- 动效克制：面板折叠 150–200ms ease-out；高亮用颜色过渡不用位移；
  **谱面重排（换行）不做动画**——那是布局重算，动画会撕裂。

## 6. 交互与状态规范

### 6.1 三向联动（核心交互）

目标状态（M3）：**谱面 ↔ 诊断 ↔ 源码** 三向互相定位。当前只有前两向。

- 点击谱面节点 → 选中该锚点 → 诊断列表滚动并高亮对应条目 → 源码面板滚动到
  对应行并高亮（新增）。
- 点击诊断条目 → 谱面滚动到对应节点并高亮 → 源码定位（新增）。
- 源码光标移动 → 反查谱面节点并高亮（新增，M3）。

锚点有四种粒度（document / voice / event / relation），高亮范围差别很大：
文档级会把整个头部框起来，声部级会框住整条声部。设计需要为"大范围高亮"给出
不刺眼的处理（当前是 2px 墨绿实线描边 + 4–6px 外扩）。

### 6.2 选中与高亮的持久性

- 缩放、换行、窗口 resize 时**必须保持选中锚点**（当前实现靠
  `renderGeneration` 在 VexFlow 异步插入节点后重扫，已可用）。
- 换文件时清空选中（当前行为）。切换视图页签时应保持。
- 跨行的 tie/slur/TAB 关系会被切成多段，**多段共享同一锚点**——高亮时应
  全部段一起亮。

### 6.3 状态清单（每个都需要设计稿）

| 状态 | 适用对象 | 当前 | 要求 |
|---|---|---|---|
| hover | 按钮、诊断条目、声部卡片、谱面可选节点 | 仅按钮有默认样式 | 谱面节点需要轻量 hover 提示（避免整页闪烁） |
| focus | 全部可聚焦元素 | **无自定义 focus 环** | 必须有清晰的键盘焦点环，与选中态视觉区分 |
| active/pressed | 按钮 | 无 | 需要 |
| selected | 诊断条目、谱面节点、声部 | 有（浅黄底 / 墨绿描边） | 统一语言 |
| disabled | 无文件时的保存/打印等 | 无 | 需要 |
| loading | 打开大文件、字体加载、导出 | 无 | 需要骨架或进度 |
| empty | 无和弦图、无诊断、无声部、无文件 | 无（空列表直接不显示） | 需要明确的空状态文案 |
| error | 仅解析通道 | 列表项浅红底 | 需要汇总入口 |
| fallback/降级 | 谱面占位节点 | 虚线框 + 红字 + 黄角标 | 需要统一"这里被降级了"的视觉语言，并可整体开关（校对模式） |
| dirty | 源码改动未重新解析 / 文档未保存 | **无任何提示** | 必须设计 |

### 6.4 校对模式（建议新增）

老用户日常看谱时不需要看到降级角标与诊断高亮，校对时需要。建议设计一个
**全局开关**："显示渲染提示"——关闭时谱面只剩纯净墨色，开启时显示角标、
虚线框、未知元素红字、诊断联动高亮。这对"打开旧谱只想看看"的主场景很关键。

### 6.5 降级标记的视觉语义

现有三类标记需要统一设计语言，严重程度递减、视觉权重也应递减：
① **未知事件**（红色虚线框 + 原文）＝"不认识这段写法，但没丢掉"；
② **越界事件**（可见文本占位）＝"这段内容不属于这种谱"；
③ **未建模构造**（倚音/圆滑线/多小节休止等，黄色角标或降级形态）＝"能显示，
但没按它本来的样子画"。

### 6.6 性能预期

- 最大真实语料约 23KB（corpus#08）。一份两声部 TAB+简谱成品（corpus#10）的
  规模：567 个歌词节点（优化后 192）、104 条关系。
- 全量渲染是同步纯函数计算，除 Staff 外无异步；**Staff 首绘需要等字体**。
- 缩放/resize 会触发整份重排（`useMemo` 依赖 `availableWidth`），设计不应要求
  "拖拽缩放滑块时实时平滑重排"——需要节流或改为离散档位（推荐离散档位）。

## 7. 无障碍与国际化

### 7.1 无障碍（当前完全未做，见 2.6）

- **键盘可达**：所有功能必须有键盘路径。重点补：谱面节点的键盘遍历（Tab/方向键
  在事件之间移动）、诊断列表的上下键 + Enter 定位、面板之间的焦点循环。
- **语义化**：当前诊断条目是 `<li onClick>`，没有 `role="button"`、没有
  `tabIndex`、没有键盘事件。谱面 SVG 没有 `role`/`aria-label`。
- **对比度**：正文 ≥ 4.5:1，大字与图形元素 ≥ 3:1。当前次级文字 `#756f65` 在
  `#f8f5ee` 上约 4.6:1（勉强），10px 的诊断文字需要提高对比或加大字号。
- **屏幕阅读器**：谱面本身难以朗读，但至少应提供：声部结构、标题元信息、
  诊断列表的完整朗读，以及"该声部含 N 个小节、M 处降级"这样的摘要。
- **焦点环**：必须有，且在深色源码面板上也可见。
- **动效**：尊重 `prefers-reduced-motion`。

### 7.2 国际化

- **默认语言中文（简体）**，英文为第二语言。当前界面是"英文标签 + 中文 aria-label +
  中文诊断文案"的混合体，必须统一。
- 诊断文案当前全为中文且含 spec 引用，英文版需要同步一套（附录 A 给出话术建议）。
- 诊断码（`jcx.*` / `muse.render.*`）**不翻译**，作为稳定标识显示在文案旁。
- 文件路径、编码名、MIDI 音色号不翻译。

## 8. 非目标

本轮设计**不做**：

1. 编辑器的语义补全 / 智能提示 / 格式化（源码面板只到语法高亮 + 行号 + 诊断标注）；
2. 协作、评论、版本历史、云同步、账号体系；
3. 移动端、平板、Web 版布局；
4. 自定义装饰记号编辑器（原软件 `AdvanceNote.exe` + `default.dec` 的能力，
   `HANDOFF.md` §50 明确规划在 M5/M6 之后）；
5. 插件系统、主题市场；
6. 谱面几何的重新设计（间距、字形大小等属 `notation/layout/metrics` 的代码改动，
   本轮只在 10.x 里提出需求，不在设计稿里逐像素定义）；
7. 原软件界面的像素级复刻——我们要的是"老用户认得出的工作流"，不是复刻 MFC 界面；
8. 五线谱的高级 engraving（beam、两端对齐、slur），这些是 VexFlow 层的能力边界。

### 附录 B — 解析诊断码分域摘要（`jcx.*`，66 条）

> 来源：`src/formats/jcx/**` 的字符串常量。级别 info/warning/error 三级都存在，
> 逐条分布未核实（见第 11 章第 1 项）。设计只需知道**有哪些域**，以支持按域分组过滤。
